## 层级解耦验证

### 设计原则：下层服务上层，下层不感知上层

#### Layer 6 → 5
- **契约**：`policy_contract.py` 定义观测/动作/控制器接口
- **解耦性**：物理仿真通过契约暴露能力，不知道上层如何使用
- **评估**：符合设计

#### Layer 5 → 4
- **契约**：`mechanism_specs.py` 提供声明式规格语言
- **解耦性**：奖励/门控通过 Expression AST 表达，运行时不依赖训练框架
- **评估**：符合设计

#### Layer 4 → 3
- **契约**：`research_supervisor.py` 暴露实验执行协议
- **解耦性**：训练运行时不知道研究协调器如何决策
- **评估**：符合设计

#### Layer 3 → 2
- **契约**：`coordinator.py` 消费 `TaskContractBundle`
- **解耦性**：基础设施执行确定性计划，不直接操作奖励或训练代码
- **评估**：符合设计

#### Layer 2 → 1
- **契约**：控制台通过 API 调用产品层
- **解耦性**：LLM 提案需审批，不能越过合同直接执行
- **评估**：符合设计
