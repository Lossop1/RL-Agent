# 端到端机器人强化学习 Agent —— 设计草案 v1

> 依据：`~/.codex/sessions/` RL 主会话 `019f40a3`（1574 条用户指令，7.08–8.04）及周边会话；
> 与工作区既有资产（`acceptance_score.py`、`spec_coverage.py`、payload/诊断/console、
> `docs/taili_*.md`）交叉对照。本文回答两个问题：
> ① 历史经验应该以什么形式沉淀；② 面向"端到端完成机器人 RL"这个任务的 agent 该有哪些设施、怎么设计。

---

## 0. 结论先行

1. **历史失败的根源不是"智能不足"，而是"过程没有被强制"。** 可枚举的失败模式：
   漂移（忘记全局要求）、局部视角（只盯一个问题）、未查清原因就加机制、狂热 fresh/重建浪费资源、
   上下文压缩导致失忆与重复工作、语义漂移（奖励/探针被钻空子）、不理解"优化而非重建"。
2. 因此历史经验**不能以叙述式教训交付 agent**（不能检索、不能检查、不能强制执行），
   必须转化为四类可执行物：**契约（代码强制）、规则（检查器强制）、协议（编排器强制）、案例（检索）**，
   再加两类支撑：**资产地图（定位）** 与 **活状态（记忆）**。
3. Agent 设计的重心是**设施与强制机制**；LLM 只在决策点推理，且决策必须经过
   **全局检查器**（把用户全程的心法制度化为闸门）才能执行。

## 1. 历史经验应该是什么样：七层知识库（KB）

### L1 契约层 —— 代码强制（"什么是通过 / 什么不允许"）
- **验收契约**：`taili_spec.md` + `acceptance_score.py`。量化门槛、家族缺失=不通过（不静默跳过）、
  部署口径（盲 / mean-action / 无特权）。这是 agent 唯一的"目标定义"，任何调参都要引用它。
- **机制契约**：奖励/门控/课程的 invariants（`taili_strategy_decisions.md` 已沉淀大半）：
  单一奖励源、per-robot 标量归约（不 raw sum）、门控只管拦截/惩罚负责塑形、无退化最优
  （静止/原地踏步永远不是更优解）、有界 shaping、**奖励=驱动、惩罚=防钻空子**。
- **禁止项（历史教训转成的硬约束）**：人工楼梯状态机、势能/接触转移式语义、
  改与当前问题无关的配置、部署依赖特权感知。
- **运行契约**：单一可编辑源（`taili_blind_config.yaml`）、权威顺序（YAML > dataclass > 文档）、
  字段→运行时可达性（"关键是配置是不是真的改了"）。
- 落地形式：lint 规则 + 契约单测 + scorer。**已存在大半，缺"禁止项 lint"。**

### L2 决策规则层 —— 检查器强制（"什么时候做什么"）
- 干预判定：仅有"停滞 / 退化 / 结构性矛盾"的量化证据才干预（连续窗口无恢复斜率、日志平台、验收族恶化）；
  resume 开头短暂上升是假象，不算趋势。
- fresh/resume 决策：历史 resume 链无法 fresh 复现时→整合成一套可复现配置，不在终点检查点硬叠加新逻辑。
- 四象限诊断协议：日志好/坏 × 实际好/坏，先对齐语义再调参；日志差时不做诊断（趋势已明）、
  日志好时用诊断确认真实、干预前必诊断。
- 优先级规则：站立 / 平地 / 楼梯同优先级并行；DR 不交换运动质量；修改不必停训练。
- 落地形式：可编程规则（检查器逐条判定），不是提示词。

### L3 协议层 —— 编排器强制（"流程怎么走"）
- 监控循环：间隔（10/20 分钟）+ 事件驱动；干预后必须"部署→启动→恢复监控"。
- 变更协议：调查原因 → 提案 → 全局检查 → （高危项人工确认）→ 执行 → 验证 → 记录。
- 压缩封存协议：压缩前自动落盘 handoff；恢复后先读状态、核对远程，再行动，不凭记忆。
- 资源协议：清理白名单保护、不并行跑多个 pytorch、本地验证防爆内存。

### L4 案例库 —— 检索（"遇到过的坑，症状→根因→处置"）
结构化字段：`{症状(可观测信号), 根因, 判定依据, 处置, 结果}`。已从历史提取的 12 条种子案例：
1. 楼梯状态机：等级恒 0 数天 → 语义没抓住本质、无驱动 → 放弃，回到"方向驱动+抬脚+足端碰撞+节律" → 破 0。
2. 门控无驱动：指标静止、放行后不涨 → 门控只拦截不产生梯度 → 补正向主驱动。
3. resume 假性上升：重启后短期上升再回落 → 分布重置余温 → 开头一段不算趋势。
4. 奖励过宽被钻空子："撞墙也算速度跟踪"、日志好实际坏 → 语义收紧 + wrong_dir 类防钻空子惩罚。
5. 奖励过窄 fresh 起不来：早期完全混乱、站立局部最优 1 万轮 → 宽核 shaping 起步、质量惩罚晚置（penalty ramp）。
6. 站立惩罚过重：站立解决但其他方向退化/急刹不自然 → 惩罚把站立变成优于运动的局部解 → 奖励为主+克制惩罚。
7. PD 硬编码不一致：mujoco 下楼梯高频振荡/上楼弹跳 → 训练 120/10 与辅助脚本不一致 → 统一 Kp/Kd。
8. 足端碰撞半径：触阶即垮、四脚张开 → 碰撞体过大 → 修正半径。
9. 特权感知与盲狗矛盾：地形感知不体现作用 → 部署无外感知 → 删除感知器，被动接触感知。
10. 过渡机制反复横跳：空中换向/卡顿/急刹多轮未收敛 → 约束定位不清（指令侧 vs 策略侧）且过强 → 移出全局要求。
11. AMP 权重嫌疑：零命令踏步 → 风格奖励过高 → 风格有限、只区分方向与静止。
12. 语义不一致：日志 progress 高但视频垮掉 → 先修指标语义，不凭单指标调参。
- 落地形式：SQLite/JSON 案例库 + 检索接口；新案例来自 L6 决策日志的自动沉淀。

### L5 资产地图 —— 定位（"东西在哪、谁是权威"）
训练/诊断/奖励/payload/配置加载的真实源码边界（`taili_runtime_source_map.md` 已存在，机器化）。

### L6 活状态 —— 记忆（"现在处于什么状态"）
`taili_live_handoff.md` 的机器化版本：当前 run / payload 哈希 / 检查点 / 趋势 / 已确定判断 /
未完成动作 / 干预条件。**压缩安全的唯一事实来源。**

### L7 元层 —— 只给人读
全局视角、奥卡姆剃刀、第一性原理等"心法"文本保留给人；agent 只见 L1–L6 的机器化形式。

## 2. Agent 面对的任务：端到端流水线

| 阶段 | 输入 → 输出 | 关键设施 | 主要风险（历史证据） |
|---|---|---|---|
| ① 任务定义 | 需求 → 验收契约(scorer) | L1 验收契约 | 目标漂移 |
| ② 系统建立 | 代码图/配置/环境 → 可跑基线 | 配置契约编辑器、codegraph | 多套生效、乱码、散乱文件 |
| ③ 训练启动 | fresh/resume 决策 → 运行中训练 | 训练执行器 + L2 fresh/resume 规则 | 狂热重启浪费资源 |
| ④ 持续监控 | 遥测 → 趋势/停滞告警 | 遥测器 + 编排器 | 不按间隔监控、看不到卡住 |
| ⑤ 诊断 | 真实行为（视频+物理量+验收家族分） | 诊断器 | 用探针替代诊断、语义不一致 |
| ⑥ 调参 | 提案 → 全局检查 → 改配置 → 部署 | 配置契约编辑器 + 全局检查器 | 未查原因就加机制、动无关项 |
| ⑦ 验收 | battery → 家族覆盖审计 | 验收执行器 | 静默跳过未测家族 |
| ⑧ sim2sim | IsaacLab → MuJoCo 迁移核对 | 诊断器（双平台）+ PD/参数核对 | PD 不一致、碰撞半径、低重心 |
| ⑨ sim2real | 部署口径验证 | 验收执行器（部署口径） | 特权依赖、口径不一致 |
| ⑩ 知识沉淀 | 决策日志 → 案例库 | 记忆系统 | 失忆后重复踩坑 |

## 3. Agent 应有的设施（9 项）

1. **训练生命周期执行器**：launch(fresh/resume)/stop/status、payload 打包部署到远程、检查点
   列表/选择/清理、数据盘清理（白名单保护）、SSH 冷却与重连。依据：反复"我部署并启动了训练"、
   "后端重启会中断训练"、"清理时保留有价值检查点"。
2. **遥测器**：结构化曲线查询、滑动均值/斜率/平台检测、停滞告警（喂给干预判定规则）、
   **只展示关键字段子集**（历史教训：所有曲线堆在一起不可读）。现状：有日志曲线，缺统计与告警。
3. **诊断器**：physeval（渲染视频 + 物理量统计 + 验收家族评分）、探针（降级为辅助）、
   结果回放接入 console、被协议约束（干预前必诊断；日志差时跳过）。现状：已存在，需接进协议。
4. **配置契约编辑器**：单源 YAML 读写、字段→运行时可达性 lint、diff/回滚、
   **影响面报告**（该字段驱动哪些验收家族，用 `spec_coverage.py`）、等价验证（旁路审计）。
   依据："多套生效/散乱/乱码让我改起来很麻烦"、"改配置前先确认字段是否真实进入运行对象"。
5. **验收执行器**：验收 battery + 家族覆盖审计（缺失=不通过）、mean-action/盲口径。
   现状：`acceptance_score.py`/`physeval_blind*` 已存在。
6. **记忆系统**：持久 KB（L1–L5，git 版本化）+ 活状态 handoff（压缩前自动封存、恢复后强制读取）+
   **决策日志**（每次干预记录 症状/判断/改动/结果 → 自动沉淀进 L4 案例库）。
7. **编排器**：监控循环调度（间隔 + 事件）、主目标跟踪（防漂移）、压缩钩子、
   干预后恢复协议（调参→部署→启动→恢复监控）。依据："20 分钟间隔监控"、"干预后要恢复训练"、
   "不要并行测试"、"修改时没必要停掉训练"。
8. **护栏**：契约单测预检、**全局检查清单（执行前必过）**、危险操作人审（远程清理/重启/大改）、
   资源限制（不并行 pytorch、内存上限、SSH 冷却）。
9. **人机界面（Console）**：智能体页展示"最关键信息"——门控差距**带具体值**、方向 progress 完整显示、
   关键趋势与当前判断；诊断回放；决策确认；状态透明（执行中 vs 卡住）。
   依据：大量 UI 纠偏（冗余字段、只有字段不给值、页面重合、白屏、诊断选不了配置）。

## 4. Agent 设计

### 4.1 设计原则（把用户全程的心法制度化为系统性质）
- **P1 单一事实源**：scorer 赢过文档（不一致时 scorer 是真相、文档是 bug）；YAML 是唯一可编辑源；
  生成物不可手改。
- **P2 决策-执行分离**：LLM 产诊断与提案；提案必须通过**全局检查器**才能执行。
- **P3 压缩安全**：所有判断先落盘（handoff/决策日志）再继续；恢复后先读状态、核对远程，不凭记忆。
- **P4 知识分层**：持久 KB ↔ 活状态 ↔ 工作上下文，三层各自独立更新；上下文只做推理缓存。
- **P5 闭环交叉验证**：日志（趋势）→ 诊断（真实）→ 配置（数学原因）→ 训练 → 验收；
  三方不一致先修语义，不凭单一指标调参。

### 4.2 全局检查器（GlobalChecklist —— 历史纠偏的机器化）
每次提案执行前逐条判定，不通过即打回：
- [ ] 原因已查明？依据是**当前** payload / 完整趋势 / 真实诊断，而非记忆或历史？
- [ ] 影响面已报告？该改动驱动/影响哪些验收家族（A–F），需要哪些配套协调？
- [ ] 未动与当前问题无关的配置？
- [ ] 奥卡姆剃刀：新增机制是否与已有语义重复、能否删掉？（禁止状态机/势能语义）
- [ ] 全局优先级一致：站立/平地/楼梯同优先级；DR 不交换运动质量？
- [ ] 契约测试通过？字段真实生效（可达性 lint）？
- [ ] 干预理由满足 L2 判定规则（停滞/退化/矛盾证据）？

### 4.3 架构选项与推荐
- **方案 A：单智能体 + 强设施 + 强检查**。一个 LLM agent 带全部设施；靠检查器/编排器强制过程。
  简单、决策连贯；风险是单点漂移（历史已证明），依赖检查器兜底。
- **方案 B：角色化多智能体**。Monitor（遥测/告警/干预判定）、Diagnostician（四象限+physeval）、
  Tuner（提案+影响面）、Reviewer（全局检查器，扮演"用户"）、Executor（部署/清理/恢复）。
  制衡清晰、单角色上下文小→压缩少；代价是状态同步与通信开销。
- **方案 C（推荐）：混合**。确定性编排层（监控循环、记忆、护栏、验收、压缩钩子全部是代码）+
  LLM 只在决策点工作（诊断、提案、案例检索）+ 提案经"规则化检查器 + LLM 评审"双保险。
  **基础设施先于智能**：历史失败大多不是不够聪明，而是过程没被强制。

**演化路径**：先按 A 落地（设施 + 检查器），当单上下文压缩压力大、漂移仍频发时，
把 Monitor/Reviewer 拆成独立角色（走向 B/C）。

### 4.4 人类在环的位置（历史中用户的实际角色）
- 授权点：远程部署/重启/清理/大改配置（高危操作确认）。
- 判断点：视觉诊断意见（用户看渲染视频，agent 读物理数据，两者交叉）、理想状态描述。
- 授权监控：用户下达"进入 10/20 分钟间隔监控，必要时干预"后，agent 才拥有干预权。

---

## 5. 落地顺序（roadmap）

1. **KB 机器化**：把 L1 契约补全（禁止项 lint）、L2 规则写成可执行检查器；`taili_session_lessons.md`
   等叙述式文档降级为 L7 元层素材，不再作为 agent 的操作依据。
2. **编排器**：监控循环、压缩钩子、干预后恢复协议（过程强制的骨架，收益最大）。
3. **配置契约编辑器**：影响面报告 + 字段可达性 lint + diff/回滚（治"多套生效/改不动"）。
4. **决策日志 → 案例库闭环**：每次干预自动沉淀案例，形成检索资产。
5. **按需拆角色**：上下文压力与漂移指标触发时，拆 Monitor / Reviewer。
