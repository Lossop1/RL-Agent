## 一、项目与目标（一句话背景）

Taili 盲狗（~39 kg、12 关节、最弱关节 thigh=110 N·m），AMP + PPO，IsaacLab/skrl 训练，
部署无外感知（无相机/高度扫描）。三条并行主线不可互相交换：**① 零命令后自然/严格/安静站立；
② 平地四方向完整运动质量；③ 以前进为主的上下楼梯（目标 25–30 cm）**；之后才是 DR 强鲁棒性。
链路：IsaacLab 训练 → MuJoCo（rl_sar）sim2sim → 真机 sim2real。

## 二、技术主线与硬结论（会话里反复验证出来的）

### 1. 楼梯/离散地形是贯穿全程的最大瓶颈
- 平地方向跟踪曾到过 8.5+，但楼梯/boxes 长期卡在等级 3～7 之间，反复"平台→停滞→干预"。
- 关键认知：**地形能力需要"驱动"（正向奖励），不是只加门控/约束**。门控只能"放行或拦下"，
  本身不产生朝目标运动的梯度。曾多次出现"只加强门控 → 无驱动 → 依旧上不去"的循环。

### 2. 人工"楼梯状态机"方案明确失败（已放弃）
- 状态机（层级切换/势能/接触转移等）投入数天，楼梯等级始终为 0（上 0 / 下 < 0.5），最终放弃。
- 教训：楼梯语义要抓住本质——**方向驱动 + 抬脚 + 碰撞允许（足端为主）+ 一定节律**，
  不要用层级/势能/接触转移等过度设计去"绕"；这被归入"没抓住关键，于是持续失败"的典型。

### 3. resume 链 vs fresh 的核心矛盾（后期最大的结构性障碍）
- 历史"楼梯 7+"能力是**多次 resume 累积**出来的，不是一套可从 fresh 复现的配置。
- 直接在成熟检查点上叠加新逻辑（如站立）resume，也难——行为已固化。
- 结论：正确路径是**保留有效的、调整/补充不足的，把历史 resume 链整合成一套可 fresh 复现的策略**，
  而不是推倒重建，也不是在终点检查点上硬加机制。
- 附带现象：resume 常"短暂上升后回落"，不能把开头一段当趋势。

### 4. 静止站立（stand-still）是后期硬骨头
- "有速度切到 0 命令后要自然、严格、安静站立"，长期做不好：踏步、摇晃、刹车过急、内八/外八。
- 尝试轨迹：加惩罚 → 奖励式站立 → 宽核 shaping 逐步收紧 → 严格惩罚。
- 结论沉淀：**奖励为主、惩罚为辅**；惩罚太重会让"站立"变成比"运动"更优的局部解，
  也可能让 fresh 阶段起不来。站立/核心稳定应在 phase0 形成，而不是靠高难度阶段纠偏。

### 5. 调参的本质：奖励是驱动，惩罚是防钻空子
- 用户原话反复强调："构造一条可靠的数学路径，让策略从最大化奖励来看**不得不**走这条路"。
- 奖励语义过宽 → 这样做那样做都能拿分 → 钻空子；过窄 → fresh 阶段找不到有效路径卡死。
- 惩罚/门控只做"安全、质量、防钻空子"的补充，不承担主驱动。

### 6. DR 域随机化分级推进
- 负重按 10→20→35→50 kg 递进；摩擦/质心/IMU 偏置/Kp-Kd/延迟/推搡配套同强度。
- 原则：**DR 不能掩盖或交换掉平地/楼梯已有质量**；楼梯的 DR 要比平地慢半拍，楼梯先保质量。

### 7. sim2sim / sim2real 的 gap（迁移必查项）
- IsaacLab 与 MuJoCo 表现不一致：下楼梯高频振荡、上楼梯接近弹跳。
- 需核对：关节 PD（训练与辅助脚本曾存在不一致硬编码，最终统一 Kp=120/Kd=10）、
  timestep（taili.xml 0.0025）、足端碰撞半径、低重心差异、部署口径（盲、mean-action、无特权）。
- 迁移到 rl_sar 时目录/配置与 rl_sar 原生结构统一，taili 放在 rl_sar 下。

## 三、调参方法论（用户在整个过程中反复强调的"心法"，可复用）

1. **全局视角**：不只看局部/短期/单一指标。平地、楼梯、DR、站立相互牵制；顾此失彼=失败。
2. **奥卡姆剃刀 + 第一性原理**：去掉冗余机制，从本质出发，先大胆假设一步到位，有必要再加边界。
3. **优化而非重建**："优化"是最高频指令——保留有用的，调整或补充不足的，不做推倒重来。
4. **语义一致性 / 交叉验证**：日志≠实际。四象限（日志好/坏 × 实际好/坏）先对齐语义；
   日志看趋势与采样覆盖、诊断物理量+视频看真实动作、实际配置看数学原因，三者不一致先修语义。
5. **先查原因再动手**：不分析清原因就一味加机制=原地打转、浪费资源。
6. **奖励为主、惩罚为辅**：见二.5。
7. **干预时机**：仅当证据表明"停滞/退化/结构性矛盾"才干预；改配置不必停训练，避免频繁重启。
8. **上下文压缩管理**：压缩前封存交接文档（run/payload/证据/判断/未完成动作），恢复后先读文档、
   核对远程状态，不凭记忆或压缩摘要当事实。

## 四、踩坑清单（高频复发，值得贴墙）

- 只加门控/约束、不给驱动 → 上不去（见二.1/二.2）。
- 频繁 fresh/resume 重启 → 浪费训练资源，且 resume 假性上升。
- 用探针/自造 smoke 替代真实交叉验证诊断 → 判断失真。
- 探针语义漂移/过复杂 → 用户多次质疑"你规定的语义到底有没有漂移"。
- 奖励定义过宽被钻空子、或过窄导致 fresh 起不来（见二.5）。
- 只改颜色/换皮的"前端" → 被驳回；设计要从"服务/目的"出发（奥卡姆剃刀）。
- 编码：中文一律 UTF-8 无 BOM；注释用中文。
- 后端重启会中断训练；本地并行跑多个 pytorch 验证会爆内存。
- 硬编码先验（3m/19cm/固定位置）不可靠，须用标定/实测数据驱动。
