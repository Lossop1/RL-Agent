# P4.2 检查点管理系统实现总结

## 完成时间
2026-09-14

## 实现概览

P4.2检查点管理系统已完整实现并集成到训练流程，提供自动化的检查点选择、清理和能力提升功能。

## 核心组件

### 1. CheckpointRegistry (检查点注册表)
**文件**: `autotuner/product/checkpoint_curator.py`

**功能**:
- 维护检查点文件到性能快照的映射
- 支持从telemetry JSONL回填历史数据
- 提供按步数范围查询、导出清单等接口

**关键方法**:
- `register(checkpoint_ref, step, performance_snapshot)`: 注册检查点及性能数据
- `get_performance(checkpoint_ref)`: 查询性能快照
- `backfill_from_telemetry(telemetry_path, checkpoint_inventory)`: 从历史数据回填
- `export_to_manifest(output_path)`: 导出JSON清单

### 2. CheckpointSelector (检查点选择器)
**文件**: `autotuner/product/checkpoint_curator.py`

**功能**:
- 多维度评分算法: 0.5×reward + 0.3×stability + 0.1×episode + 0.1×recency
- 过滤条件: reward阈值、terminal_rate上限、最小训练步数
- 识别里程碑检查点: phase转换点、历史最佳reward

**关键方法**:
- `score(performance, weights, recency_base_step)`: 计算综合得分
- `filter_candidates(registry, criteria)`: 根据条件过滤候选
- `rank_top_k(candidates, k, weights)`: 排序并返回top-K
- `select_milestones(registry)`: 识别里程碑检查点

**默认阈值**:
- `min_reward_ratio`: 0.3 (30%最大值)
- `max_terminal_rate`: 0.2 (20%终止率上限)
- `min_training_step`: 50000 (最小训练步数)

### 3. CheckpointCurator (检查点清理器)
**文件**: `autotuner/product/checkpoint_curator.py`

**功能**:
- 分层保留策略: top-10 + recent-5 + milestones + 历史最佳 + 24h内
- 归档策略: 7天以上低性能检查点 → archive/
- 删除策略: 30天以上 → 永久删除
- 磁盘占用监控和强制清理

**关键方法**:
- `apply_retention_policy(checkpoint_dir, registry, policy)`: 应用保留策略
- `trigger_cleanup_if_needed(checkpoint_dir, registry, threshold_gb)`: 基于阈值触发清理
- `archive_checkpoint(checkpoint_path, archive_dir)`: 归档操作
- `delete_checkpoint(checkpoint_path)`: 删除操作
- `compute_disk_usage(checkpoint_dir)`: 计算磁盘占用

**默认保留策略**:
```python
{
    "top_k": 10,              # 保留top-10高性能
    "recent_k": 5,            # 保留最近5个
    "recent_hours": 24.0,     # 保留24小时内全部
    "archive_age_days": 7.0,  # 7天以上归档
    "delete_age_days": 30.0,  # 30天以上删除
    "score_threshold_percentile": 50.0,  # 低于50%百分位归档
}
```

### 4. CapabilityPromotionService (能力提升服务)
**文件**: `autotuner/product/checkpoint_curator.py`

**功能**:
- 从高性能检查点提取能力特征
- 创建CapabilityProfile记录写入研究账本
- 批量提升top-K检查点

**能力维度**:
- `speed_range`: low / low_to_medium / medium_to_high (基于reward_mean)
- `terrain_levels`: phase_N, uneven_terrain, obstacles (基于curriculum_phase)
- `command_modes`: 从配置提取 (如forward, turn, strafe)
- `quality_gates`: stability, endurance, reward_threshold (基于性能阈值)

**关键方法**:
- `extract_capabilities(checkpoint_ref, performance, config)`: 提取能力特征
- `create_profile(checkpoint_ref, capabilities, status)`: 创建CapabilityProfile
- `promote_top_performers(registry, selector, ledger_store, top_k, config)`: 批量提升

### 5. CheckpointIntegration (统一集成接口)
**文件**: `products/taili/blind_locomotion/checkpoint_integration.py`

**功能**:
- 整合Registry、Selector、Curator、Promotion四大组件
- 提供统一的on_checkpoint_saved回调接口
- 管理周期性清理和训练结束处理

**配置参数**:
- `cleanup_interval`: 每N个检查点触发一次清理 (默认10)
- `cleanup_threshold_gb`: 磁盘占用阈值 (默认90.0GB)
- `enable_cleanup`: 是否启用自动清理 (默认True)
- `enable_promotion`: 是否启用能力提升 (默认True)

**关键方法**:
- `on_checkpoint_saved(checkpoint_path, step, performance)`: 检查点保存回调
- `finalize_training(top_k, config)`: 训练结束最终处理
- `get_statistics()`: 获取统计信息
- `export_manifest(output_path)`: 导出清单

### 6. checkpoint_hook (训练流程钩子)
**文件**: `products/taili/blind_locomotion/checkpoint_hook.py`

**功能**:
- 在训练流程中安装CheckpointIntegration
- 拦截telemetry_emit的checkpoint回调
- 训练结束时执行最终清理和能力提升

**接口**:
- `install_checkpoint_hook(agent, env, checkpoint_dir)`: 安装钩子
- `finalize_checkpoint_management(env, config)`: 训练结束处理

### 7. checkpoint_curator_cli (命令行工具)
**文件**: `products/taili/blind_locomotion/checkpoint_curator_cli.py`

**功能**: 手动检查点管理操作

**命令**:
```bash
# 选择top-K检查点
python -m products.taili.blind_locomotion.checkpoint_curator_cli \
    --checkpoint-dir ./checkpoints \
    --telemetry ./telemetry.jsonl \
    select --top-k 10

# 执行清理
python -m products.taili.blind_locomotion.checkpoint_curator_cli \
    --checkpoint-dir ./checkpoints \
    cleanup --threshold-gb 50.0

# 提升检查点为CapabilityProfile
python -m products.taili.blind_locomotion.checkpoint_curator_cli \
    --checkpoint-dir ./checkpoints \
    --telemetry ./telemetry.jsonl \
    promote --top-k 5

# 查看状态
python -m products.taili.blind_locomotion.checkpoint_curator_cli \
    --checkpoint-dir ./checkpoints \
    --telemetry ./telemetry.jsonl \
    status
```

## 集成点

### train_taili.py
```python
# runner.run()前安装钩子
try:
    from .checkpoint_hook import install_checkpoint_hook
    checkpoint_dir_path = str(Path(os.environ.get("TAILI_CHECKPOINT_DIR", str(run_dir / "checkpoints"))))
    install_checkpoint_hook(runner.agent, env.unwrapped, checkpoint_dir_path)
except Exception as e:
    print(f"[TAILI_TRAIN] checkpoint hook install failed: {e}", flush=True)

runner.run()

# finally块执行最终清理
finally:
    try:
        from .checkpoint_hook import finalize_checkpoint_management
        finalize_checkpoint_management(env.unwrapped, config=experiment_cfg)
    except Exception as e:
        print(f"[TAILI_TRAIN] checkpoint finalize failed: {e}", flush=True)
```

### telemetry_emit.py
```python
def checkpoint(self, checkpoint_path: str, step: int) -> None:
    """检查点保存回调，触发性能快照注册"""
    # 注册到CheckpointIntegration
    if hasattr(self._env, "_checkpoint_integration"):
        performance = self._extract_performance_snapshot()
        self._env._checkpoint_integration.on_checkpoint_saved(
            checkpoint_path, step, performance
        )
```

## 工作流程

### 训练期间
1. 每次保存检查点时，telemetry_emit.checkpoint()被调用
2. checkpoint_hook拦截回调，提取性能快照
3. CheckpointIntegration.on_checkpoint_saved()注册到Registry
4. 每10个检查点触发一次周期性清理(可配置)
5. CheckpointCurator执行分层保留策略

### 训练结束
1. train_taili.py的finally块调用finalize_checkpoint_management()
2. CheckpointIntegration执行最终清理
3. CapabilityPromotionService提升top-K检查点
4. CapabilityProfile记录写入研究账本(如果启用)

## 性能特性

### 评分算法
```python
score = 0.5 * (reward_mean / reward_max) +          # 奖励维度 (50%)
        0.3 * (1.0 - terminal_rate) +                # 稳定性维度 (30%)
        0.1 * min(episode_length / 150.0, 1.0) +     # 持久性维度 (10%)
        0.1 * exp(-age_hours / 24.0)                 # 新鲜度维度 (10%, 24h半衰期)
```

### 保留决策树
```
检查点 → 是否在top-10? → 保留
      ↓ 否
      → 是否在recent-5? → 保留
      ↓ 否
      → 是否为milestone? → 保留
      ↓ 否
      → 是否在24h内? → 保留
      ↓ 否
      → 年龄>30天? → 删除
      ↓ 否
      → 年龄>7天 且 性能<50%分位? → 归档
      ↓ 否
      → 保留
```
